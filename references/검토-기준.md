# 검토 기준

> 스킬-구조-점검 의 딸린 자료다. 6단계에서 새 스크립트를 검토하거나 다른 모델에게 검토를 맡길 때 읽는다.

다른 모델에게 독립 검토를 맡겼을 때 실제로 나온 결함의 갈래다. 새 스크립트마다 아래를 차례로 본다. 맡기는 글은 `assets/검토-맡기는-글.md`.

## 볼 것

- **경계 판정**: 파이썬의 `\b` 와 `\w` 는 한글도 낱말 글자로 본다. "3번에" 처럼 조사가 붙은 번호나 이름을 놓친다. 한글 둘레는 경계를 직접 적는다.
- **새로 생긴 폴더**: `git status` 는 새 폴더를 한 줄로만 보여 주어 그 안의 파일을 놓친다. `git status -uall` 로 본다.
- **닫힌 것과 지난 것**: 취소됐거나 날짜가 지난 항목에도 동작이 되는가(지난 일정에 알림을 보내는 식).
- **"없음"의 뜻**: 글자가 하나도 없음과 한글이 없음, 파일이 없음과 비어 있음을 섞지 않았는가.
- **종료 코드**: 맨 위 설명과 실제 종료 코드가 맞는가. 고른 것이 하나도 처리되지 않았는데 0 으로 끝나지 않는가.
- **글자 틀**: EUC-KR 이라 적힌 글을 cp949 로 읽는가(EUC-KR 로 읽으면 일부 글자가 깨진다).
- **결과보다 오류 글**: 결과가 나왔는데 오류 글을 먼저 보고 실패로 판정하지 않는가(경고만 찍는 도구가 많다).
- **빈 값의 이름표**: 값이 비었을 때 붙이는 설명이 다른 경우에도 맞는가(모든 빈 값이 같은 까닭은 아니다).
- **쓰는 자리**: 결과 파일이 원본이나 다른 기록을 덮을 수 없는가. 날짜나 이름 인자로 폴더 밖에 쓸 수 없는가(`../`).
- **묶음 풀기**: 압축을 풀 때 밖으로 나가는 경로, 바로가기, 장치 파일을 거르는가.
- **이상한 입력**: 빈 글자, 객체가 아닌 JSON, 음수, 0.
- **가리는 범위**: 개인정보를 가린다고 적었으면, 무엇을 가리고 무엇이 보이는지가 설명과 같은가.
- **시험이 덮지 못한 행동**: 시험이 없는 갈래를 따로 묻는다. 거기서 결함이 가장 많이 나온다.

## 답을 받으면

- 결함마다 시험을 먼저 더해 실패하는 것을 본 뒤 고친다.
- 결함이 아니라고 보면 까닭을 한 줄로 남긴다(같은 지적이 다시 나오지 않게).
